# /harness-plan — 기획 전담 스킬

인자: `$ARGUMENTS`

신규 프로젝트와 기존 프로젝트 모두에서 독립적으로 사용 가능하다.

## 실행 순서

### 1. 현재 컨텍스트 파악

```bash
python flow.py status
```

`plan/spec.md`가 존재하면 읽어서 기존 목표·기능·범위를 파악한다.  
기존 태스크 목록도 확인해 이미 계획된 작업과 중복이 없는지 체크한다.

컨텍스트별 시작 메시지:

- **신규 프로젝트** (spec.md 없음): 빈 상태에서 전체 기획 시작
  > "어떤 걸 만들고 싶으세요? 거칠게라도 말씀해 주시면 제가 구체화해 드릴게요."

- **기존 프로젝트** (spec.md 있음): 추가/변경 사항 기획
  > "현재 [프로젝트명]에 [기존 기능 요약] 이 있어요. 어떤 걸 추가하거나 바꾸고 싶으세요?"

### 2. 기획 대화 루프

AI가 대화를 주도하며 스펙을 **결정될 때마다 즉시 spec.md에 추가**한다.  
전체를 완성한 뒤 한꺼번에 쓰지 않는다. 확정된 항목만 그때그때 기록한다.

#### 반복 사이클 (항목별로 반복)

**① 대화로 탐색**  
자유롭게 대화하며 해당 항목을 구체화한다.  
선택지가 있으면 옵션을 번호로 제시한다:
> "인증 방식은 어떻게 할까요?  
> 1안. JWT (stateless, 모바일 친화적)  
> 2안. 세션 쿠키 (서버 관리 필요, 웹에 적합)"

사용자가 떠올리지 못한 고려사항이 있으면 AI가 먼저 제안한다.

**② 확정 확인**  
방향이 잡히면 spec.md 기록 전에 반드시 확인한다:
> "1안 JWT로 spec에 추가할까요?"

**③ 즉시 기록**  
사용자가 OK하면 해당 항목을 바로 `plan/spec.md`에 append한다.  
추가 후 짧게 확인:
> "추가했어요. 다음은 [다음 항목] 얘기해 볼까요?"

**④ 다음 항목으로**  
신규 프로젝트면 전체 섹션을 순서대로 채운다.  
기존 프로젝트면 변경/추가되는 섹션만 업데이트한다.

권장 섹션 순서:

| 순서 | 항목 | spec.md 섹션 |
|------|------|-------------|
| 1 | 목표 | `## 목표` |
| 2 | 핵심 기능 | `## 핵심 기능` |
| 3 | 기술 스택 | `## 기술 스택` |
| 4 | 범위 제외 | `## 범위 제외` |
| 5 | 제약 조건 | `## 제약 조건` |
| 6 | 기타 결정 | `## 기타 결정 사항` |

항목이 해당 없으면 "해당 없음"으로 기록하고 넘어간다.

#### 종료 조건
사용자가 "됐어", "이걸로 가자", "완료" 등을 말하거나 모든 섹션이 기록되면 루프 종료.

### 3. 기획서 검토

`plan/spec.md`를 읽고 `plan/review.md`에 검토 결과 작성:
- 목표가 명확한가?
- 핵심 기능이 구체적인가?
- 범위가 적절한가? (너무 많거나 너무 적지 않은가)
- 기술 스택이 목표에 적합한가?
- 기존 기능과 충돌하거나 중복되는 부분은 없는가?
- 빠진 고려사항이 있는가?

작성 후 사용자에게 검토 결과를 요약해서 보여주고 확인을 구한다:
> "검토 결과예요. [주요 피드백 요약]. 이 방향으로 태스크 분해할까요?"

사용자가 수정을 요청하면 spec.md를 업데이트하고 검토를 다시 수행한다.  
OK가 나오면 4단계로 진행한다.

### 4. 태스크 분해

spec.md 기반으로 태스크를 **먼저 목록으로 제시**하고, 사용자 확인 후 추가한다.  
기존 프로젝트라면 이미 존재하는 태스크와 중복되지 않도록 주의한다.

**① 분해 목록 제시**
```
[제안 태스크 목록]
1. 태스크 제목 (설명)
2. 태스크 제목
3. 태스크 제목 (태스크 2 완료 후 가능)
...
```
- 각 태스크는 독립적으로 완료 가능해야 함
- 너무 크면 세분화 (하루 이내 완료 기준)
- 의존 관계가 있으면 명시

**② 사용자 확인**
> "이렇게 나눌까요? 추가하거나 빼고 싶은 태스크 있으신가요?"

수정 요청이 있으면 목록을 조정하고 재제시한다. OK가 나오면 ③으로 진행.

**③ 일괄 추가**
```bash
python flow.py plan log "태스크 분해 근거: ..."

python flow.py task add "태스크 제목"
python flow.py task add "태스크 제목" --desc "상세 조건이나 구현 힌트"
python flow.py task add "의존 태스크" --parent <부모id>
```

### 5. 기획 로그 기록

```bash
python flow.py plan log "기획 완료: <태스크 수>개 태스크 생성"
```

### 6. Phase 전환

현재 phase에 따라 다르게 처리한다:

- **planning** → implementation 전환:
  ```bash
  python flow.py phase next --force
  python flow.py files snap
  ```

- **implementation / testing** → 이미 진행 중이므로 phase 전환 불필요.  
  새 태스크가 backlog에 추가되었음을 안내하고 `/harness-status`로 이어가도록 유도한다.

- **shipped** → 새 작업 시작:
  ```bash
  python flow.py phase back   # 또는 적절한 phase로 복귀
  python flow.py files snap
  ```

### 7. 사용자에게 보고

- 추가된 태스크 목록
- 다음 할 일: `/harness-status`로 첫 번째 태스크 시작
